# 架构与事件语义

## 运行范围

仅 Windows 10/11 + Python 3.11 经过验证。标准库 HTTP 收发与本地图片渲染并不等于跨平台服务支持：Windows 启动脚本、`pythonw.exe`、进程锁、PowerShell 停止流程和字体选择需要单独适配。常态通知无需保持 QQ WebSocket；WebSocket 只用于一次性接收者绑定。

## 组件

| 文件 | 职责 |
| --- | --- |
| `notifier.py` | 配置检查、HTTP 接收、签名验证、事件解析、只读会话查询、去重、QQ API 发送。 |
| `message_card.py` | 本机 Markdown 解析与 PNG 排版，不访问资源 URL。 |
| `pair_bot.py` | 临时连接 QQ 网关，用随机短语获得当前 Bot/环境下的单聊 OpenID。 |
| `configure.py` | 仅在本地 `.env` 不存在时从示例创建配置并生成随机签名密钥；不修改 Hermes。 |
| `supervisor.py` | 独立看门狗、单目录进程锁、通知进程退出后的退避重启。 |
| `start-hidden.cmd` / `autostart.vbs` | 隐藏启动看门狗；VBS 按自身所在目录解析路径。 |
| `start.cmd` | 前台启动看门狗，用于调试。 |
| `stop.cmd` / `stop.ps1` | 写入 `.stopped`，按本目录入口路径定位并停止看门狗与通知进程，不按端口杀其他服务。 |
| `manage_autostart.py` | 安装、移除或查看当前用户登录自启；不隐含启动/停止服务。 |
| `integrations/hermes/` | outbound 列表模板及可选桌面注册插件模板；不含本机秘密。 |

通知服务与 Hermes 进程独立，关闭 Hermes 不自动停止服务。登录自启不是系统服务，用户登录前不运行。看门狗重启的是进程，不负责重放历史通知。

## 数据流与信任边界

```text
[实际使用的 Hermes 客户端 / profile]
  outbound 订阅 + HERMES_NOTIFY_SECRET
                │ HTTP POST /event
                │ X-Hermes-Signature-256: sha256=<HMAC>
                ▼
[本机 127.0.0.1:<port>，notifier.py]
  请求长度检查 → 签名验证 → JSON / 事件名解析
                │
                ▼
  内存队列（最多 512 项，单工作线程消费）
                │
                ▼
  筛选 → 会话元信息 → 摘要 / 去重键 → 发送前去重标记
                │            ▲
                │            └─ HERMES_HOME/state.db（只读）
                ▼
  本机 Markdown 排版 → PNG 字节，或短文字
                │ HTTPS：取 token / 上传 / 发送
                ▼
[QQ 官方 API 与接收者客户端]
```

- Hermes 的 webhook 载荷可能包含整段历史；**本机接收到的范围大于最终发到 QQ 的摘要**。不要将回环 HTTP 改成公网入口。
- `NOTIFY_SECRET` 与 Hermes `.env` 的 `HERMES_NOTIFY_SECRET` 相同。签名针对原始请求体，防止不知道密钥的请求伪造；它不加密正文，也不是带时间戳的防重放协议。
- 服务只读查询 `state.db` 的会话标题、来源、目录、分支等元信息，不将它当作通知消息库。缺失或不可读时可退化为会话 ID；`--check` 不建库。
- 标题、提问、回复摘要、命令、错误、来源/分支、目录名都可能出现在通知中。截断、移除链接和省略代码块不是秘密检测或可靠脱敏。
- PNG 在内存生成，不使用第三方图床、不下载正文资源；**上传后仍受 QQ 的存储、分发与客户端缓存边界影响**，不能称为数据始终不离开本机。
- 本地 `.env`、凭证文件、去重状态、日志、Hermes 数据及环境文件均是私有运行数据，不应作为公开仓库内容。日志和异常信息也可能暴露上下文，提交问题前应最小化并脱敏。

## 接收、排队与送达不是同一件事

`GET /health` 提供进程运行信息、计数及队列长度，`service: "hermes-qq-notify"` 用于识别服务。健康并不证明凭证有效、平台许可发送或接收者已经看到消息。

`POST /event` 验证后返回 `202`，发送在后台进行：

1. `202` 不是持久化确认，也不是 QQ 送达确认。
2. 队列仅在内存中，进程崩溃、停止或系统重启会丢失待处理事件。
3. 队列满时丢弃事件；当前接收路径仍可能返回 `202`，调用方不能据此推断成功排队。
4. 不支持持久 outbox、失败补偿或死信队列；看门狗不会恢复丢失的消息。
5. 不符合事件筛选条件的载荷也可以被接收，但不会生成通知。

因此这是尽力而为的提醒通道，不适合唯一的审批记录、告警审计或关键业务投递。

## 事件筛选

### 完成：`post_llm_call`

需要非空最终回复。默认 `ONLY_TOOL_TURNS=1`，从当前轮历史末尾向前检查工具调用，遇到用户消息停止；已知纯聊天跳过，历史缺失时无法判断，可能仍推送。

通知包含时间、会话信息、用户提问摘要和最终回复摘要。正文默认最多 1400 字，代码块省略，完整内容仍应在 Hermes 查看。「任务完成」只是此事件的呈现文案，不证明所有外部副作用或业务验收成功。

### 审批：`pre_approval_request`

显示命令和说明，要求回到 Hermes 审批。`surface=smart` 的自动判断阶段不提醒；真正人工审批是否触发取决于 Hermes 版本与客户端路径。本项目不改变审批策略，不执行远程允许/拒绝。

### 提问：`pre_tool_call` + `clarify`

只处理工具名为 `clarify` 的调用，支持 `questions[]` 和旧版单问题格式；显示问题、选项、多选标记，数量和长度有上限。

这是**调用前提醒**，不是 pending 状态机：用户可能已经回答，或工具随后校验失败；已发送图片不会撤回。必须从真实目标客户端产生提问并确认 QQ 到达，手工载荷测试不能证明客户端会派发该事件。

### 错误与结束

`api_request_error` 显示模型 API 错误摘要，不涵盖所有工具失败。`on_session_end` 默认关闭，必须同时在 outbound 列表中订阅并设置 `NOTIFY_SESSION_END=1`。

## 去重与失败语义

去重状态保存在本地 `state.json`，**不是消息正文队列**。窗口为 90 秒：完成事件基于会话/轮次，审批基于会话/命令，提问优先使用 Bot、环境、会话和调用 ID（无调用 ID 时用问题内容回退），错误与结束使用相应事件键。缺失轮次 ID 等字段可能造成不同事件被合并；超过窗口也可能重复通知。

去重标记在实际 QQ 发送之前写入。发送失败不会撤销标记，也没有补偿重试；同键重投递在窗口内仍可能被抑制。状态文件写入失败也会影响跨重启去重。因此不提供「恰好一次」、不丢不重或可靠有序承诺。

QQ token 在本地缓存；发送遇到认证失效可刷新后再尝试，不能等同于通用投递重试。图片上传显式禁止上传阶段自动发送，再独立发送媒体消息。图片准备/上传失败可降级短文字；真正发送图片后遇到失败或超时不补发文字，因为远端可能已经接受，只是本机没收到响应。成功计数也不等于客户端已读。

## 排版与容量限制

Pillow 与 markdown-it-py 完成本地排版。支持标题、粗体、列表、引用和简化表格；正文资源不解析下载，代码块省略，装饰 emoji 可被移除。除了回复摘要字数上限，还有渲染输入长度、图片高度与大小限制，长通知可能进一步截断或降级文字，不保证与 Hermes 原文完全一致。

## 生命周期

`start-hidden.cmd` 和 `start.cmd` 清除 `.stopped` 后启动看门狗。`stop.cmd` 写入该标记并停止本目录进程，标记跨重启保留；仅再次登录或直接运行 VBS 不会解除停用。

自启 `install` 只注册当前用户登录启动项，不立即启动；`remove` 只移除注册，不停止已运行服务。目录迁移后必须重新注册，使启动项指向新位置。单目录锁不替代跨目录、跨 Bot 的身份协调。

## 非目标

不提供 QQ 双向聊天、远程回答/审批、公网接入、多租户隔离、历史同步、持久消息队列、离线补发、固定主动消息额度、跨 AppID/环境身份合并或跨平台运维支持。安装与测试见 [README](../README.md)，切换与回滚见 [迁移指南](MIGRATION.md)。
